# 🚀 Azure Data Factory (ADF) - Real-Time Enterprise Scenarios

هذا المستودع يحتوي على تطبيقات عملية لأنابيب معالجة البيانات (**Data Pipelines**) في **Azure Data Factory (ADF)**، تم إعدادها لمعالجة تحديات هندسة البيانات الشائعة في بيئات العمل الحقيقية مثل أتمتة التحميل، معالجة المخططات الديناميكية، والتنظيف التلقائي.

---

## 📌 نبذة عن المشروع (Project Overview)

يهدف المشروع إلى بناء حلول هندسة بيانات مرنة وقابلة للتوسع (Scalable & Reusable) لنقل وتحويل البيانات بين بيئات التخزين المختلفة، مع التركيز على:
* **تقليل وقت وتكلفة المعالجة:** من خلال التحميل المتزايد والتعامل مع الملفات الحديثة فقط.
* **المرونة في معالجة الهياكل:** معالجة التغير المباشر في مخططات البيانات (Schema Drift) والربط الديناميكي.
* **إدارة موارد التخزين:** التنظيف التلقائي للملفات المؤقتة والمعالجة.

---

## 🛠️ التقنيات المستخدمة (Tech Stack)

* **Orchestration Tool:** Azure Data Factory (ADF)
* **Data Lake Storage:** Azure Data Lake Storage Gen2 (ADLS Gen2)
* **Databases:** Azure SQL Database / Azure Synapse Analytics
* **Formats:** JSON, Parquet, CSV

## 🏗️ شرح الأنابيب والسيناريوهات (Pipelines & Scenarios)

### 1️⃣ `incrementalload.json` - سيناريو التحميل المتزايد (Incremental Load)
* **الهدف:** نقل البيانات الجديدة أو التحديثات الحاصلة في المصدر فقط (Delta Load) بدلاً من إعادة تحميل الجدول بالكامل (Full Load).
* **آلية العمل:**
  * استخدام عمود المتابعة (Watermark Column مثل `LastModifiedDate` أو `ID`).
  * مقارنة آخر قيمة تم تحميلها بقيم المصدر لاستخراج البيانات الحديثة فقط.
  * تحديث جدول المتابعة (Watermark Table) بعد إتمام كل عملية بنجاح لضمان استمرارية التحميل الدقيق.

---

### 2️⃣ `Source Sink Match.json` - سيناريو مطابقة المصدر والهدف (Source & Sink Column Matching)
* **الهدف:** ضمان توجيه ومطابقة البيانات بشكل صحيح عندما لا تتطابق أسماء الأعمدة أو ترتيبها بين نظام المصدر ونظام الاستهداف.
* **آلية العمل:**
  * استخدام التعيين الصريح (Explicit Column Mapping) داخل أنشطة النقل.
  * ضمان تحويل وتطابق أنواع البيانات (Data Types) بين المصدر والهدف وتفادي خطأ انقطاع البايب لاين عند اختلاف الترتيب.

---

### 3️⃣ `Fresh Files.json` - سيناريو معالجة الملفات الحديثة فقط (Fresh Files Ingestion)
* **الهدف:** معالجة واستيعاب الملفات الجديدة أو التي أضيفت مؤخراً إلى بحيرة البيانات فقط، وتجاهل الملفات القديمة المعالجة سابقاً.
* **آلية العمل:**
  * التصفية بناءً على تاريخ التعديل الأخير للملف (`Last Modified Date`).
  * قراءة خصائص الملفات المتاحة في الحاوية عبر `Get Metadata Activity` وتحديد الملفات المستحدثة لمعالجتها فقط لتوفير الموارد.

---

### 4️⃣ `deletefiles.json` - سيناريو إزالة وحذف الملفات (Delete / Housekeeping)
* **الهدف:** أتمتة إدارة التخزين وحذف الملفات المؤقتة أو القديمة بعد نجاح عملية النقل والمعالجة.
* **آلية العمل:**
  * تنفيذ **`Delete Activity`** بناءً على مسار مخصص أو شرط زمني (مثل الملفات الأقدم من عدد معين من الأيام).
  * تنظيف مجلدات المعالجة المؤقتة (Staging Areas) لمنع تضخم المساحات وتوفير تكاليف ADLS Gen2.

---

### 5️⃣ `Dynamic schema mapping.json` - سيناريو الربط الديناميكي للمخطط (Dynamic Schema Mapping)
* **الهدف:** بناء بايب لاين مرن قادر على التعامل مع جداول ومخططات بيانات متغيرة (Schema Drift) دون الحاجة لإنشاء بايب لاين ثابت لكل جدول.
* **آلية العمل:**
  * قراءة هيكل المخطط (Schema Metadata) ديناميكياً باستخدام Parameters أو JSON Configuration.
  * ربط الأعمدة برمجياً ومباشرة أثناء وقت التشغيل (Runtime) مما يجعل البايب لاين قابلاً لإعادة الاستخدام مع أي جداول جديدة تلقائياً.
